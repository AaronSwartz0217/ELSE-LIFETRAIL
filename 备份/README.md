## 归档规则

- **站点大改前**：先 `git commit`（见下方「版本管理」），不要再用「复制 `public/`」。git 已接管回退，手工副本只会和仓库分叉。
- **数据文件作废**：连同作废原因移入 `备份/日期_数据归档/`，并在 `../数据/必读/03_数据地图.md` 注明去向与接手者。
- **不再新增其他命名风格**：一律 `日期_对象_说明`。

## 版本管理

项目根目录已纳入 git，远端为 GitHub 私有仓库，回退靠 commit 而不是靠复制文件夹：

| 想做什么 | 命令 |
|---|---|
| 存一个还原点 | `git add -A && git commit -m "说明"` |
| 看历史 | `git log --oneline` |
| 撤销某个文件未提交的改动 | `git restore <文件>` |
| 整体退回某个提交 | `git reset --hard <commit>` |
| 从旧提交开个分支继续改 | `git branch 想回的点 <commit>` |

> 清单里 3 份 `2026-10-03_*lifetrail-web*/` 是 git 之前的手工副本，保留作历史，不再新增同类。
> 只有确实需要「脱离 git 的单文件快照」时，才用 `git archive -o 备份\日期_lifetrail-web_说明.zip HEAD`。
