# ELSE-LIFETRAIL

> 一套**纯本地**的三端体系：把散落多年的个人日志，整理成可核验、可回退、能用来做规划与复盘的自我管理系统。
>
> 无云、无外部服务、无第三方依赖 —— 后端只用 Node.js 内置模块，数据全部落在你自己的硬盘上。

## 一、为什么是「三端」

大多数个人记录工具的问题是：**记录、结论、行动是三件事，却被塞进同一个地方**。于是结论写错时，你查不出它是从哪条记录推出来的；行动失效时，也没法回头修改当初的判断。

这套体系把三件事拆成三个独立的端，各自只干一件事，再靠「可追溯」把它们串起来：

```
一端 · 输入（只读）
  日志/YYYY-MM-DD/*.txt  +  同名图片目录
  只负责如实落盘：不解释、不总结、不改写
        │
        │  按日期索引
        ▼
二端 · 加工（结构化 / 解释 / 判断）
  数据/必读/     每次加载的第一层，规定「必须先读什么」
  数据/          全量索引 · 主分析入口 · 阶段与时间轴说明
  数据/dlc/      补丁 · 快照 · Skills
  只负责把记录变成结论：每条结论都要能追回原文
        │
        │  结论 → 站点的可视化数据
        ▼
三端 · 呈现（站点 / 运行时）
  lifetrail-web/   server.js（Node 内置模块）+ public/
  只负责把结论变成可看、可改、可对话的界面
```

**贯穿三端的唯一硬约束**：二端的每条结论都必须能追回一端的原文（`[日期｜标题｜日志ID]`）。追不回去的结论，不该存在。

## 二、三端各自是什么

| 端 | 目录 | 内容 | 谁在写 | 可写性 |
|---|---|---|---|---|
| 一端 · 输入 | `日志/` | 按日期分目录的 `.txt` 原始日志 + 图片 | 本人 | **只读**（归档后不再改） |
| 二端 · 加工 | `数据/` | 全量索引、主分析入口、阶段与时间轴说明、DLC 补丁、必读层 | 本人 + AI | 可改，但要留版本 |
| 三端 · 呈现 | `lifetrail-web/` | 站点后端、前端页面、运行时状态（`data/`） | 人 + AI | 可改 |

二端里嵌了一层**引导层** `数据/必读/`：它规定「每次对话、每次改站之前必须先读什么」，防止加工端随对话漂移。新增日志照着 `数据/必读/04_日志更新协议.md` 的 A→E 清单走一遍即可。

## 三、三端给出的界面

| 页面 | 回答的问题 |
|---|---|
| 总览 | 整体现在处于什么状态 |
| 时间轴 | 这些年是怎么排布的 |
| 阶段 | 每一段发生了什么、真正变在哪 |
| 动作 | 我实际做了什么、留下了什么痕迹 |
| 判断 | 我下过哪些判断、结果如何 |
| 计划白板 | 接下来要做什么（可拖拽便签墙） |
| 评价 | 一份不客气的体检报告 |
| 身体 | 作息与精力的长期走势 |
| 更新 | 站点改过什么 |
| 对话 | 在证据边界内和模型对话 |

## 四、跑起来

```bash
cd lifetrail-web
node server.js
```

打开 <http://127.0.0.1:3217>

- **零依赖**：只用 Node.js 内置模块，不需要 `npm install`。
- **只绑本机**：仅监听 `127.0.0.1`，不对局域网或公网开放。
- **接口鉴权**：`/api/*` 除来源校验外还要求携带 `X-LifeTrail-Token`；令牌在首次启动时自动生成到 `lifetrail-web/data/auth-token.txt`，所以它不入库也不影响新设备启动。

> 站点是**本地运行时**，不是可部署到服务器的在线服务。克隆到新设备后照上面两步即可跑起来。

## 五、版本与回退

整个项目用 git 管理，远端为私有仓库。回退靠 commit，而不是靠复制文件夹：

```bash
git add -A && git commit -m "说明"     # 存一个还原点
git log --oneline                      # 看历史
git restore <文件>                     # 撤销某个文件未提交的改动
git reset --hard <commit>              # 整体退回某个提交
git branch 想回的点 <commit>           # 从旧提交开分支继续改
```

新设备拉取：

```bash
git clone git@github.com:AaronSwartz0217/ELSE-LIFETRAIL.git
```

SSH 鉴权认的是**你 GitHub 账号上的公钥**，和仓库是公开还是私有无关。新设备上生成一对密钥、把公钥加进账号即可：

```bash
ssh-keygen -t ed25519 -C "设备名"
# 把 ~/.ssh/id_ed25519.pub 的内容加到 GitHub → Settings → SSH and GPG keys
ssh -T git@github.com    # 返回 "Hi <用户名>!" 即为通过（退出码非 0 属正常）
```

## 六、什么不入库

`.gitignore` 只排除**活密钥**，与隐私无关 —— 密钥被公开仓库的爬虫扫到，就是实打实的损失：

| 文件 | 为什么排除 |
|---|---|
| `lifetrail-web/data/auth-token.txt` | 站点 API 的有效令牌；首次启动会自动重建 |
| `lifetrail-web/data/ai-config.local.json` | 「外接模型」模式下会存第三方接口 Key（会计费） |

日志、对话记录、白板、判断等个人内容**都在版本控制里**，可以随 commit 一起回退。
