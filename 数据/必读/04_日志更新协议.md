# 日志更新协议

> 每次往 `../../日志/` 里加或改一篇日志后，照本清单走一遍。
> 目的不是「全自动」：篇数、年份柱这类是**算术**，站点自己会算；阶段、转折点、评价这类是**判断**，只能重跑。本协议把「哪些自动、哪些要重跑、怎么验收」写死，防止结论与原文脱节。

## 0. 适用范围

- 只覆盖**日志内容线**：新增一篇 / 修订已有 / 补回图片。
- 站点功能与 UI 改动不在这里，走 `../../lifetrail-web/public/app.js` 的 `DEMO.changelog`。
- 触发后按 **A → E 顺序**执行，每步验收过再进下一步。

## A. 落盘（原始层 · 手动）

| # | 动作 | 验收 |
|---|---|---|
| A1 | 文件放 `日志/YYYY-MM-DD/`，命名 `YYYY-MM-DD_标题_ID.txt` | 服务端只索引匹配 `^\d{4}-\d{2}-\d{2}_.+\.txt$` 的文件，命名不合进不了站 |
| A2 | 图片放**同名子目录**（`…_ID/001.png`），并配 `图片索引.txt` | 子目录名 = txt 主名 |

## B. 站点索引（机械 · 不要手改）

| # | 动作 | 验收 |
|---|---|---|
| B1 | 站点点「导入日志清单」，或重启 `node server.js` | `GET /api/stats` 的 `logs` 变化正确 |
| B2 | 总览「日志底图」、时间轴 / 阶段 / 评价页说明里的篇数 | 由 `LOG_COUNT` 自动同步，无需手改 |
| B3 | 时间轴年份柱、阶段页逐月图 | 按 `date` 自动变，无需手改 |

## C. 数据侧索引（机械）

| # | 动作 | 验收 |
|---|---|---|
| C1 | 重生成 `../日志全量索引.json`：新增一条 `date/title/id/path/chars/comments/ocr/images` | 条目数 = `/api/stats` 的 `logs` |
| C2 | 更新 `03_数据地图.md` §3 计数基线（日期改成当天） | 篇数 / 年份分布与磁盘一致 |

> C1 目前仍是手工；理想是从日志目录或 `/api/stats` 直接生成，别再抄。

## D. 语义重跑（判断 · AI 重跑 + 本人确认）★

新日志**可能改变结论**（补一篇旧年份的，会动到阶段边界）。逐条自问，命中就重跑：

| # | 触发条件 | 要重跑的地方 |
|---|---|---|
| D1 | 新日志落在某阶段起止附近，或补的是旧年份 | `../阶段与时间轴重写说明.md`；如是，站点 `records.json` 里对应阶段的 summary / boundary / evidence / change / unresolved |
| D2 | 新日志构成新的「结构性 / 过程性」转折 | 站点 `index.html` 的「全量分析 · N 个转折点」段落、`app.js` 的转折点数据 |
| D3 | 新日志足以改变六维评分或某条锐评 | `app.js` 的 `REVIEW`（评分与评语是判断，不是事实）。**评价标准（2026-10-20 起）**：`REVIEW.latest` 新增一条时必须① `verdict` **不少于 1500 字**；② **具体**——点名日志日期/标题、引用原话或数字，不做泛泛概括；③ 用 `**…**` **标出重点**（渲染成金色底纹高亮）；④ `watch` 为**可执行指引**，每条带时限与验收动作，不写空方向；⑤ **保留**——只在 `REVIEW.latest` **最前面新增**，**不得删除或覆盖旧条**，旧条在评价页默认折叠、可点击展开看全文（verdict + watch），历史不丢；⑥ **迭代**——新增时必须把上一条里**尚未收尾**的 `watch` 用 `carry` 字段显式承接（渲染成「承接上条 · 仍开」区块），已收尾的才从承接里去掉，防止旧指引被忘掉；⑦ **赋分**——每条必须带 `score.items` 六项（分析力 / 行动力 / 主体性 / 复原力 / 自省诚实度 / 判断转化），总分 = 六项平均，页面自动与上一条逐项比较并显示 **+/−**（绿=加分、红=减分）；评分是判断，涨跌只表示这一批日志相对上一条的变化方向 |
| D4 | 出现新人名 / 关系变化 / 阶段结论变化 | `../../lifetrail-web/data/model-brief.md`（注入 AI prompt 的那份简报） |
| D5 | 需要更新主分析入口 | `../AI问答与个人助手知识库分析.md` 的 §16 索引、年度分布、目录树 |
| D6 | 新日志命中某条学习路线的进度 / 坑 / 依据 / 下一步 | `../../lifetrail-web/data/learning/<file>.md`（步骤勾选、坑、依据、下一步）与 `../../lifetrail-web/data/learning.json`（`updated_at`、该路线的 `state`）——「学习」页是后端知识库，站内只读现取；新增 / 完成的 step 必须有日志出处 |

**验收**：重跑后，受影响的每条结论都能追回原文（`[日期｜标题｜日志ID]`），且数字与 B / C 步一致。
**边界**：拿不准要不要重跑时，宁可跑一遍再确认，别把旧结论留在那儿当「现状」。

## E. 收尾

| # | 动作 | 验收 |
|---|---|---|
| E1 | 站点显示内容变了 → `app.js` 的 `DEMO.changelog` 顶部加一条 | 更新页能看到 |
| E2 | 本目录与相关文件的 `version` / `updated_at` | 与改动一致 |
| E3 | `git add -A && git commit -m "更新日志：…"`；要异地备份再 `git push` | `git status -sb` 干净，`git log --oneline -1` 是本轮 |

> E3 取代了旧的「复制 `public/` 到 `../../备份/`」：回退交给 git，手工副本只会和仓库分叉（见 `../../备份/README.md`）。
> 提交前扫一眼 `git status`：`auth-token.txt` 与 `ai-config.local.json` 不在列表里才对，它们已被 `.gitignore` 排除。

## 附 · 一句话版本

> 加日志 → 导入 → 重生成索引 → 自问是否动到阶段 / 转折点 / 评价 / 学习路线 → 重跑并确认 → 更新 changelog → commit。
