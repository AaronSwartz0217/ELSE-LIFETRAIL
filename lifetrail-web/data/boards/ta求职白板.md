## 第 3 题

标签：第一档 · 必会 · 列：1 · 状态：未完成

dot(N, L) 在 Lambert 里干什么；结果为负说明什么？cross(a,b) 的方向怎么定（右手系下）？

参考要点：
- N·L 是光线与法线夹角的余弦 cosθ，就是 Lambert 漫反射的受光强度
- 结果为负 = 光源在表面背面，没有漫反射贡献 → 要 clamp 到 0，否则出现负光照
- cross(a,b) 在右手系下满足右手定则：四指从 a 转向 b，拇指指向即结果方向
- 前提：N 与 L 必须在同一空间且都归一化，否则强度算错

想深入：Lambert 与 Disney 漫反射（半兰伯特、Oren-Nayar）的差别。

## 第 9 题

标签：第三档 · 区分度 · 列：1 · 状态：未完成

shader_feature 和 multi_compile 的区别是什么？keyword 爆炸你怎么量化地解决（不只是「少用」）？

参考要点：
- 两者都按 keyword 生成 shader 变体：multi_compile 的所有组合都会编译进包并在运行时可控；shader_feature 只保留材质实际用到的变体，未使用的会被剥离
- 量化：先把 keyword × 取值列成矩阵，算出变体总数 = 各 keyword 取值数的乘积，按乘积排序，找到贡献最大的那一列
- 收敛：低频组合改成材质属性/分支而不是 keyword；互斥或可推导的 keyword 合并（用枚举属性替代多个 bool）
- 控制影响面：用 #pragma multi_compile_local / shader_feature_local，避免污染全局 keyword
- 建立变体统计与打包报告，对超阈值的 shader 单独管理——先量化再决定砍哪一列，而不是盲目「少用」

想深入：Unity 的变体收集与剥离（ShaderVariantCollection、IPreprocessShaders）；UE 的 Static Switch 与变体烘焙。

PBR 的 Cook-Torrance 模型里 D / F / G 三项各管什么？「能量守恒」体现在哪一句？金属度工作流里 Albedo 和 Metallic 两张图各自存了什么？

参考要点：

- 金属度工作流：Albedo 里对非金属存漫反射色、对金属存 F0；Metallic 是 0/1 遮罩，用于在两者之间切换

## 第 7 题

标签：第二档 · TA 面试高频 · 列：2 · 状态：未完成

Bloom 的实现流程：为什么必须先提亮再降采样？Tonemapping 在整个后处理链的哪个位置、为什么必须在那？

参考要点：
- Bloom 流程：按阈值（soft knee）挑出高亮区 → 多次降采样成金字塔 → 各层模糊 → 上采样叠加回原图
- 先提亮再降采样：降采样本质是求平均，若先模糊，暗部能量会摊薄、整幅图变糊变灰；先提亮保证只有高亮区参与
- Tonemapping 在 Bloom 之后、最终输出之前——它把 HDR 线性值压到 0–1 显示范围
- 必须在所有 HDR 处理之后：先压回 LDR 就丢了高光动态范围，Bloom 也就没得可做；顺序：HDR → Bloom → Tonemapping → 色彩分级/输出

想深入：ACES 等色调映射曲线；UE 的 Bloom 参数（阈值、强度、方法）在 HDR 管线里的位置。

## 第 10 题

标签：第三档 · 区分度 · 列：2 · 状态：未完成

Niagara GPU 粒子：模拟结果怎么回读到 Gameplay（比如拿粒子位置做碰撞或生成 Mesh）？涉及哪些 Buffer/UAV 概念？

参考要点：
- GPU 粒子在 GPU 上模拟，数据存在 Sim Texture / Buffer 里；要回到 Gameplay 必须「回读」（readback），把 GPU 数据拷回 CPU 可访问的内存
- 做法一：用 Niagara Data Channel 或自建 RWStructuredBuffer 承载粒子数据
- 做法二：异步回读——先拷到 Staging Buffer，隔若干帧再映射读取，避免同步 stall
- 做法三：把粒子位置导出到渲染目标/纹理，供其它系统采样使用
- 几个关键概念：Structured Buffer、UAV（可读写视图）、Staging Buffer、异步回读的帧延迟（几帧延迟是常态，别指望同帧拿到）
- 工程注意：同步回读会 stall 渲染管线，必须异步 + 允许延迟；碰撞这类需求一般优先在 GPU 端直接算

想深入：Niagara Data Channel 与「GPU 粒子 → 碰撞 → 生成 Mesh（Niagara Mesh Renderer / ISM）」的落地方式。

## 第 2 题

标签：第一档 · 必会 · 列：3 · 状态：未完成

法线为什么不能直接用同一个世界矩阵变换？要用什么矩阵，为什么？

参考要点：
- 世界矩阵若含非均匀缩放（或剪切），法线方向会被带歪——法线与切线保持垂直，而这个矩阵不保持垂直关系
- 要用「逆转置矩阵」：(M⁻¹)ᵀ；矩阵只含旋转或均匀缩放时，(M⁻¹)ᵀ 退化为 M，可直接复用
- 推导：切线 t ⊥ n（t·n=0）不代表 Mt ⊥ Mn，但 Mt · ((M⁻¹)ᵀ n) 仍为 0
- 工程做法：统一用逆转置最省心，只在确定无缩放时才走捷径

想深入：骨骼蒙皮时法线怎么跟着蒙皮矩阵走；法线归一化为什么不能省。

## 第 5 题

标签：第二档 · TA 面试高频 · 列：3 · 状态：未完成

TBN 矩阵是什么？法线贴图为什么存在切线空间而不是世界空间？切线为什么要正交化（或为什么用 MikkTSpace）？

参考要点：
- TBN 由切线 T、副切线 B、法线 N 构成正交基，三列就是 T、B、N，即「切线空间 → 世界」的变换
- 切线空间法线贴图可平铺、可被不同 UV 复用、能跟随骨骼变形；世界空间法线烘死后绑死在这个模型上，不能复用
- 从 UV 和顶点位置反算的 T 往往与 N 不严格垂直，直接组矩阵会让法线倾斜、接缝发暗；需 Gram-Schmidt 正交化，B = cross(N,T)·w（w 处理 UV 镜像的手性）
- MikkTSpace 是统一的切线生成规范，保证不同工具/引擎算出的切线一致，减少跨软件接缝

想深入：UV 镜像（w=−1）时法线为什么出现接缝；「切线空间 vs 物体空间」在移动端上的取舍。

## 第 8 题

标签：第二档 · TA 面试高频 · 列：3 · 状态：未完成

Draw Call 的开销主要由什么构成？GPU Instancing / Static Batching / SRP Batcher（UE 侧对应机制）三者的适用条件和本质区别是什么？

参考要点：
- Draw Call 开销主要来自 CPU 侧：提交指令、状态切换（shader 变体 / 材质 / 常量缓冲 / 贴图）、驱动与图元设置——瓶颈是 CPU，不是 GPU 画得慢
- GPU Instancing：同一 mesh + 同材质一次提交多个实例，适合大量相同物体（草、石头），靠实例数据区分
- Static Batching：把不动的物体焊成一个合并 mesh，减少提交次数；代价是显存/包体变胖，且失去单独剔除
- SRP Batcher（UE 侧对应自动合批 / 管线状态缓存）：不合并 mesh，而是按相同 shader 变体聚拢常量缓冲，减少状态切换；适合材质多但 shader 一致的大量小物体
- 本质区别：Instancing 是「一次画多个」，Static Batching 是「把多个焊成一个」，SRP Batcher 是「压低每次之间切换的成本」

想深入：SRP Batcher 与 GPU Driven 管线（UE 的 Auto Instancing / Nanite）的关系；常量缓冲布局为什么影响合批失败。

## 第 11 题

标签：第三档 · 区分度 · 列：3 · 状态：未完成

半透明物体为什么不能写 ZWrite？如果一定要正确的半透明遮挡，OIT 有哪几种思路，各自的代价是什么？

参考要点：
- 半透明写 ZWrite 会让后画的物体被深度测试挡掉，或让半透明互相遮挡出现硬边；半透明需要混合，而混合要求按从远到近排序且不产生硬遮挡
- ① 深度排序（画家算法）：按到相机距离排序后依次混合；代价是排序开销，且互相穿插的几何无法正确排序
- ② 逐像素深度剥离（Depth Peeling）：一层层剥出最近表面，拿到全部层再混合；代价是渲染次数 × 层数
- ③ 加权平均混合（WBOIT）：用权重近似任意顺序混合，一次渲染；代价是结果只是近似，不适合高精度场景
- ④ 逐像素链表（PPLL）：每个像素存一个片元链表，最后统一排序混合；代价是显存与带宽消耗大
- 没有免费方案，按「精度 vs 代价」在排序 / 剥离 / 加权 / 链表之间取舍

想深入：UE 的 OIT 插件（如 OIT 半透明）；折射类半透明为什么常用「后处理 + 深度」近似。

## 第 1 题

标签：第一档 · 必会 · 列：3 · 状态：未完成

模型空间一点 P，变到世界空间再到观察空间，矩阵乘法顺序是什么？（说清你用行向量还是列向量）

参考要点：
- 列向量约定（Unity / UE / OpenGL 习惯）：矩阵写在左边左乘，v = M_view · M_world · M_model · v，即「先局部→世界→相机」

- 两种写法算出的结果一致，只是转置关系；真正要记住的是变换顺序：model → world → view
- 若还要进裁剪空间，投影矩阵排在最前（列向量）或最后（行向量）

想深入：M = T · R · S 的合成顺序为什么是缩放→旋转→平移（而不是反过来）。

## 第 4 题

标签：第一档 · 必会 · 列：3 · 状态：未完成

引擎内部旋转为什么用四元数而不是欧拉角？万向锁到底是什么锁住了？

参考要点：
- 欧拉角有三个分量，但存在次序依赖、插值会绕远路，以及万向锁
- 四元数用「轴 + 角」的 4 个数表示旋转，可归一化、可球面插值（slerp），适合累积和混合
- 万向锁：三个万向环中，当第二个轴转到 ±90°，第一轴与第三轴重合，失去一个自由度
- 本质是欧拉角这种参数化在特定点降维，不是机械卡死；引擎内部存四元数，只在编辑器里换算成欧拉角给人看

想深入：slerp 与 nlerp 的差别；四元数双覆盖（q 与 −q 表示同一旋转）带来的插值问题。
