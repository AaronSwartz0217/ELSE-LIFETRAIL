# 技术美术（TA）迁移

## 目标
把已有的 ShaderToy → ShaderLab/GLSL 工作流整体迁到 UE5，形成能写进简历、能对接美术与程序的技术美术能力。

## 步骤
- [x] ShaderToy 找代码 → 转 ShaderLab 的 CG 语义块 / GLSL（10-22：这条迁移本身可作 TA 能力证据写进作品集）
- [x] UE5 材质 Custom 节点：输入输出/数组手动增删、内置函数、return
- [x] RT（Render Target）→ 后处理材质链路；理解渲染队列 / z-buffer 的排序发生在光栅化阶段（处理的是光栅化出的 RT 数据）
- [~] 渲染管线打底：应用（CPU 配置/决定渲染）→ 几何（顶点着色器、曲面细分）→ 光栅化（片元/像素着色器）→ 后处理；MVP 四坐标系与正交 / 透视投影仍不够深，z-buffer 的数据组成未搞清
- [~] D3D12 延迟管线 + AI 接入（课设方向）：输出 render target / z-buffer / g-buffer，经像素流或 DLSS5 交给 AI 做后处理级优化，AI 作为黑盒
- [~] Pass / SubShader / v2f：Pass = 容器兼函数（顶点 + 片元逻辑，输出颜色 / 深度缓冲）；v2f = 在 Pass 内部流转的数据 / 参数；SubShader = 按平台留优化余地的适配层；多个 Pass 叠出最终像素
- [~] 光照算法：着色器本质是对光向量的解析与重构，光只是辅助向量；光照的数据结构与完整处理流程待补（10-22 指定任务）
- [~] ush / hlsl：项目外的 shader 文件（自定义 ush 需放在工程外 shader 目录）+ 热编译 → 封装后交 Custom 节点使用
- [~] 插件层开发：蓝图 / C++ 做便于美术取用的工具流；相关功能块已迁到 GitHub 备投递
- [~] 体积渲染 / 高斯渲染：UE5 原生支持，转过去不必像 Unity 那样重写或接插件
- [ ] 把 RT 结果渲染到 GBuffer / 后处理体积；全屏 pass 与管线级 Pass 的统一理解
- [ ] 作品集配套：浅水方程 / 鸟群算法 / Niagara 粒子 / 特殊交互 / DX12 / ShaderToy 迁移 / 人物概念图

## 坑
- ush（Unreal Engine Shader Head）要放在 UE5 工程外的 shader 目录，蓝图无法被 VS/rider 直接识别
- 纯蓝图跑这套前期成本高；要么蓝图+C++，要么纯 C++
- Custom 节点做不了 ush 那种「蜘蛛网」函数封装，复杂逻辑仍需 ush
- 自研 WebGL 管线（不用 three.js）遇到 z-buffer / 渲染队列问题：所有函数都得自己搭，写脚本做冒烟测试修管线
- 血条这类「百分比」参数是间接参数（要经变换），参数声明在 CG 语义块而非 Properties（Properties 更像槽位）
- 没有同赛道的人做标准衡量，方向容易错乱：需要技术美术社群提供差距参照，光问 AI 顶不住压力
- 开发实际功能时用工具类函数调用会绕开 MVP 等底层本质，边做边学深入原理本身是矛盾的
- 容易把 v2f 误当成结构体或一条固定流程；它实际是被 Pass 调用的数据
